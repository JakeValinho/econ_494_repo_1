## Assignment

Reproduce a main result from an AER paper in a programming language different from the authors' original implementation, inspect the original code for coding or reproducibility issues, and evaluate their effects.

The authors use **Stata**. This repository reproduces **Table 5** in **R**.

## Target: Table 5 — Total expenditure and saving regressions

The original replication package has now been traced. Table 5 is generated by `hh-survey-results.do` using the cleaned `urban_lprob.dta` dataset and the saved bootstrap draws in `boot_results.dta`.

The published table has four columns:

| Column | Outcome | Post coefficient | Interaction coefficient | N | R² |
|---|---|---:|---:|---:|---:|
| (1) | Total spending | 264.1 | 647.2 | 2745 | 0.152 |
| (2) | Total spending, expenditure < $5,000 | 198.2 | 403.1 | 2681 | 0.186 |
| (3) | Bonus saved | -5.590 | 95.95 | 2681 | 0.034 |
| (4) | Bonus spending variable* | 0.0742 | 152.4 | 2339 | 0.048 |

`*` The original Stata code incorrectly gives the column (4) variable the display label “Cash gifts received.” The variable itself is constructed as reported soldiers' bonus spending. See `audit/audit_log.md`.

## How the original Table 5 works

The authors:

1. use the cleaned household/Census dataset `urban_lprob.dta`;
2. run four OLS regressions with the same age/race/state control structure;
3. use the predicted probability of veteran status interacted with the relevant post-bonus indicator;
4. obtain standard errors from 1,000 bootstrap replications;
5. bootstrap entire **city clusters within strata** and re-estimate veteran probability inside every draw;
6. insert the bootstrap SDs into the final regression table.

The supplied `boot_results.dta` reproduces the published Table 5 standard errors exactly up to rounding.

## Run the main reproduction

From the repository root:

```r
source("R/02_reproduce_table5.R")
```

This script:

- translates the exact Stata control structure into R;
- estimates all four Table 5 columns with `lm()`;
- calculates the published standard errors from `boot_results.dta`;
- compares coefficients, SEs, N, and R² with the published values;
- writes comparison files to `output/`;
- automatically flags values that do not match within a small rounding tolerance.

Expected outputs:

```text
output/table5_reproduced.csv
output/table5_published_vs_reproduced.csv
output/table5_replication_checks.csv
```

## Independently reproduce the bootstrap

To reproduce the bootstrap logic itself in R:

```r
source("R/03_full_bootstrap.R")
```

The default is 1,000 replications. For a quicker test from a terminal:

```bash
REPS=50 Rscript R/03_full_bootstrap.R
```

The R bootstrap will not generate the exact same random draws as Stata even with seed 123 because the programs use different random-number implementations. The economically relevant check is whether the resulting bootstrap standard errors are close to the authors' saved bootstrap standard errors.

## Audit findings so far

See `audit/audit_log.md` for full details. The main findings are:

1. **Column 4 labeling error.** The dependent variable is bonus spending, but the Stata display label says “Cash gifts received.” This affects interpretation, not numerical estimates.
2. **Main bootstrap block commented out.** The section of `run_bootstrap.do` that regenerates `boot_results.dta` is commented out as shipped. The supplied saved draws still reproduce the published SEs.
3. **$5,000 wording discrepancy to test.** The table says observations above $5,000 are omitted, while the code uses `tot_expen < 5000`, which also excludes exactly $5,000. The numerical effect depends on whether such observations exist.
4. **Hard-coded local paths.** Original Stata files require editing an author-specific Dropbox path before they run.
